# Fire Atlas

Фронтенд исследовательского сервиса для трека NASA Space Apps **Flame in Freefall**. Восемь экранов связывают вопрос, исследования NASA PSI, условия опытов, измерения, доказательства, сценарий миссии и отчёт.

Этот этап реализует FE-01–FE-14 на мок API. Реальная подготовка корпуса, поиск, AI и сборка PDF принадлежат серверной части. Демонстрация явно помечена в интерфейсе; синтетические записи не выдаются за результаты NASA.

## Запуск

Нужны Node.js **22.19+** и pnpm **10.28.2** (версия закреплена в `packageManager`).

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Открыть [http://127.0.0.1:5173](http://127.0.0.1:5173). Мок API стартует до первого запроса приложения. Гостевой выбор и задачи демо хранятся в IndexedDB; перезагрузка страницы их сохраняет.

## Подключение бэкенда

Создать `apps/web/.env.local` по примеру `apps/web/.env.example`:

```dotenv
VITE_USE_MOCKS=false
VITE_API_BASE_URL=/api/v1
API_PROXY_TARGET=http://127.0.0.1:8000
```

```sh
pnpm dev:api
```

Доступ к API проходит через один клиент с `credentials: include`. Для локальной разработки Vite проксирует `/api` на `API_PROXY_TARGET`. Для отдельного API-origin нужны разрешённый origin, CORS с credentials и корректные cookie сервера. Приложение не содержит ключей модели и не обращается к провайдеру AI напрямую.

Предварительная схема: `packages/contracts/openapi.yaml`. Типы генерируются из неё:

```sh
pnpm contracts:generate
pnpm contracts:check
```

До интеграции BE должен согласовать предварительные уточнения из [описания интеграции](docs/frontend-integration.md). Замена моков сервером не требует замены экранных компонентов.

## Сборка и проверки

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm build:demo
pnpm test:e2e
pnpm format:check
```

`build` создаёт клиент для реального API, `build:demo` — отдельную демонстрационную сборку. Результат находится в `apps/web/dist`. Команда `pnpm preview` открывает последнюю собранную версию. Статический хостинг должен возвращать `index.html` для маршрутов приложения; `/api` обслуживает бэкенд.

На Windows браузерные тесты используют установленный Microsoft Edge. На Linux/macOS сначала выполнить `pnpm exec playwright install chromium`. Браузер можно выбрать переменной `PLAYWRIGHT_CHANNEL`, адрес уже запущенного приложения — `E2E_BASE_URL`. HTML-протокол сохраняется в `playwright-report`, снимки и трассы — в `test-results`.

## Демонстрационный маршрут

1. Ввести вопрос о вентиляции и твёрдых материалах на обзоре.
2. Найти BASS-II, открыть карточку и основание; сохранить исследование и добавить в сравнение.
3. Открыть измерения FLEX и выбрать `30CAL03`: диаметр **1,92 мм**, время **6,34 с**.
4. Добавить FLEX в сравнение, проверить различия методов.
5. Запустить AI-пример и сохранить ответ.
6. Выбрать лунную базу: увидеть ограничение прямых данных; старый ответ сохранит исходную миссию.
7. Выбрать материалы в отчётах, подготовить экспорт и скачать маркированный PDF-пример.

PDF в демо подготовлен заранее и **не отражает текущий состав пространства**. Настоящий отчёт по снимку должен собирать сервер без повторного запуска AI.

## Структура

- `apps/web` — React, маршруты, компоненты, API-клиент и демонстрационный MSW API.
- `packages/contracts` — предварительный OpenAPI 3.1-контракт.
- `tests/e2e` — пользовательский маршрут, сбои, доступность и четыре ширины экрана.
- `docs` — интеграция, ограничения и приёмка фронтенда.

Основные библиотеки: React, TypeScript, Vite, React Router, TanStack Query, CSS Modules, Recharts, Radix Dialog, MSW, Vitest и Playwright. Шрифты Manrope и IBM Plex Mono включены локально; их лицензии находятся в `apps/web/public/licenses/fonts.txt`.
